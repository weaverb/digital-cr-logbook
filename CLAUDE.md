# CLAUDE.md

Guidance for Claude Code working in this repository.

## Read this first

**[AGENTS.md](./AGENTS.md) is the source of truth** for PR/commit policy, ATF
compliance rules, build/test gates, and the target-user persona. It's
agent-agnostic (written to cover Gemini, Copilot, Claude, and others) — read
it before making changes, and don't duplicate its rules here. If a rule here
and a rule in AGENTS.md ever disagree, AGENTS.md wins; fix this file.

The short version, expanded on in AGENTS.md:
- No direct pushes to `main` — every change goes through a PR.
- **Open the PR, don't merge it.** The maintainer reviews and merges by hand
  (auto-merge was explicitly turned off on this repo — don't re-enable it or
  pass `--auto`/`--merge` on a `gh pr` command unless told to).
- Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, …) — semantic-release
  depends on this.
- This app is 100% offline/local — never add telemetry, analytics, or network
  calls that phone anything home.
- ATF bound-book records are compliance-sensitive: disposed records are
  immutable, edits require a logged reason (`ATF_AUDIT_LOG`), and legal
  citations use the shared `CfrLink` / `AtfRulingLink` components.
- Before opening a PR: `bun run test` and `bun run build` must pass. Any new
  user-interactable feature also needs a Playwright test in `e2e/`, not just
  Vitest coverage — that's been asked for explicitly on every UI feature so
  far. Aim for close to 100% code coverage on new code (`bun run test:coverage`).
- Before committing anything under `cr_list/` (or any other generated
  script/doc), strip local machine identifiers — home directories, usernames,
  absolute paths — out of it first. This bit the project once already.

## What this project is

**C&R Collector Digital Logbook** — an offline, privacy-first desktop bound
book and collection-management app for FFL Type 03 Curio & Relic collectors,
built for compliance with 27 CFR § 478.125(f) and ATF Ruling 2016-1. Full
product context: [PRODUCT.md](./PRODUCT.md). Full schema/architecture:
[software_architecture_plan.md](./software_architecture_plan.md).

## Stack

- **Package manager / runtime**: Bun (v1.3+) — use `bun`, not `npm`/`yarn`/`pnpm`.
- **Frontend**: React 19 + TypeScript + Vite, Tailwind CSS v4.
- **Desktop shell**: Tauri v2 (Rust) — `src-tauri/`. SQLite in WAL mode.
- **Backup encryption**: BIP-39 seed phrase → AES-256-GCM / Argon2id (`.crbk`
  archive format), in `src/lib/cryptoVault.ts`.
- **Testing**: Vitest (unit), Playwright (e2e, in `e2e/`).
- **Lint**: oxlint.
- **Releases**: semantic-release, fully automated on merge to `main` (see
  `.releaserc.json` and the release-standards section of README.md) — don't
  hand-edit `CHANGELOG.md`, version fields, or `docs/index.html` download
  links; they're generated by `scripts/update-version-files.js` during release.

## Commands

```bash
bun install          # install deps
bun dev              # web dev server (fast, no Rust/GTK needed)
bun run build        # tsc -b && vite build
bun run lint         # oxlint
bun run test         # vitest run
bun run test:watch
bun run test:coverage
bun run test:e2e     # playwright
bun run tauri:dev    # native desktop window (needs GTK/webkit2gtk deps, see README)
bun run tauri:build  # standalone desktop binary
```

## Repo map

- `src/components/` — modals & UI (acquisition, disposition, audit log,
  backup vault, PDF export, contacts rolodex, command palette, etc.)
- `src/lib/` — `storage.ts` (localStorage + audit log engine), `cryptoVault.ts`
  (BIP-39/AES vault), `pdfExporter.ts` (ATF-compliant PDF), `fileSaveHelper.ts`,
  `osHelper.ts`.
- `src/data/cr_master_data.json` — pre-compiled offline ATF C&R reference
  database (4,200+ records); source CSV and regeneration script live in
  `cr_list/` (see `cr_list/README_CR_LIST.md` for the update workflow). The
  CSV is the source of truth (extracted from official ATF publication PDFs)
  and ships baked into every release, but the app also lets a user
  drop-and-replace it at runtime with a newer CSV before the app itself gets
  upgraded — that import path dedupes/amends against existing entries. It has
  previously hit a `localStorage` quota error on a full 4,200+ row import;
  watch for that if you touch the import path.
- `src/types/logbook.ts` — domain model / TypeScript interfaces.
- `src-tauri/` — Tauri v2 Rust desktop engine (window config, native fs/dialog
  capabilities).
- `e2e/` — Playwright end-to-end tests.

## Conventions specific to this codebase

- Keyboard-first UX matters (older, non-technical target audience): `Ctrl/Cmd+K`
  command palette, `Esc` closes modals via `src/hooks/useEscapeKey.ts` — keep
  new modals consistent with that pattern.
- Dark "gunmetal & slate tactical" theme, high contrast, dense data tables —
  match existing Tailwind tokens in `src/index.css` rather than introducing a
  new palette.
- Legal/compliance copy always links out through `CfrLink` / `AtfRulingLink`
  (`src/lib/legalLinks.tsx`), never a bare URL.
- Never delete tests or wrap broken code in a silent `try/catch` to make CI
  pass — fix the root cause (also stated in AGENTS.md).

## Release pipeline: hard-won lessons

This pipeline has broken in specific, previously-fixed ways — don't reintroduce
these:

- **Job order matters.** Version calculation/sync (`scripts/update-version-files.js`)
  must run and commit *before* the Tauri binaries are compiled, or the binaries
  embed the stale `APP_VERSION` while the GitHub Release gets tagged with the
  new one — breaking support triage (this happened once, in the botched
  `v1.2.0` release).
- **`deploy-pages.yml` must stay on `workflow_run`**, not `push: branches: [main]`.
  A push trigger fires on the pre-release merge commit — before
  `semantic-release` has rewritten `docs/index.html`'s download links to the
  new version — and the `[skip ci]` release commit that follows never
  re-triggers it, so Pages serves stale/404 download links. It must listen for
  the release workflow's completion instead.
- **`.releaserc.json` needs `"changelogTitle": "# Changelog"`** on the
  `@semantic-release/changelog` plugin, or release headings get prepended
  above the changelog's own title line.
- **Only `.exe`, `.dmg`, `.AppImage`, and `.deb` are actually built.** No
  `.msi` — a stale "Download Windows MSI" button on the GitHub Pages site
  pointed at a nonexistent asset once; don't reintroduce an MSI reference
  without actually wiring up an MSI build.
- Release titles read `v{VERSION} - C&R Digital Logbook`, version first —
  that's a deliberate ordering, not incidental.
- Branch protection on `main` was intentionally relaxed so the release bot
  (`semantic-release` via `@semantic-release/git`) can push its
  `chore(release): …  [skip ci]` commit directly. That's an exception for the
  automated pipeline, not a green light for an agent to push to `main`
  directly — that still requires explicit one-off authorization from the
  maintainer, same as AGENTS.md says.
