# AGENTS.md — AI Agent Guidance & Operating Directives

> **Project:** C&R Collector Digital Logbook  
> **Repository:** `weaverb/digital-cr-logbook`  
> **Compliance:** 27 CFR § 478.125(f) & ATF Ruling 2016-1  

This document defines mandatory operating rules, architectural guidelines, and workflow policies for all AI coding agents (including Google Antigravity, Gemini, GitHub Copilot, Claude, and autonomous subagents) working in this repository.

---

## 🛑 1. Pull Request & Commit Policy

### ⚠️ Mandate: All Changes via Pull Requests
- **No Direct Pushes to `main`**: All code modifications, documentation updates, configuration changes, or bug fixes generated by an AI agent **MUST** be submitted as a Pull Request (PR) against the `main` branch.
- **Human Code Review**: Direct pushes to `main` by AI agents are **strictly prohibited** unless explicitly authorized by the repository maintainer in the prompt.
- **Branch Naming Convention**:
  - Features: `feat/description-of-feature`
  - Fixes: `fix/description-of-bug`
  - Documentation: `docs/description-of-update`
  - Refactor/Chore: `chore/description-of-task`

### 📝 Conventional Commits
All commit messages must follow the [Conventional Commits](https://www.conventionalcommits.org/) specification to ensure automated Semantic Versioning (SemVer) and CHANGELOG generation:

- `feat:` -> Triggers **Minor** version bump (`1.0.0` -> `1.1.0`)
- `fix:` / `perf:` / `security:` -> Triggers **Patch** version bump (`1.0.0` -> `1.0.1`)
- `BREAKING CHANGE:` / `!:` -> Triggers **Major** version bump (`1.0.0` -> `2.0.0`)
- `docs:` / `chore:` / `ci:` -> Does not trigger a version bump

## 🔒 2. Privacy & Offline Architecture

- **100% Local & Offline**: The application operates completely offline. **Zero remote telemetry, zero analytics, zero cloud tracking, and zero automatic background submissions.**
- **Local Data Storage**: Firearm records, maintenance logs, range logs, and contacts are stored in local browser/Tauri storage (SQLite / WAL mode).
- **Manual User Submissions Only**: Support requests or GitHub issue submissions are strictly manual copy-and-paste actions initiated by the user.

---

## 📜 3. Legal & ATF Compliance Rules

- **27 CFR § 478.125(f)**: Bound book entries must record exact required fields for acquisitions and dispositions.
- **ATF Ruling 2016-1**:
  - Disposed records are permanently locked against non-audit deletion.
  - Amendments to existing bound book entries are tracked with an immutable audit log (`ATF_AUDIT_LOG`).
- **Legal Documentation Links**:
  - Use centralized legal link components (`CfrLink` and `AtfRulingLink` in `src/lib/legalLinks.tsx`) for user-visible references.
  - Hyperlink `27 CFR § 478.125(f)` to official eCFR and `ATF Ruling 2016-1` to ATF.gov PDF.

---

## 🛠️ 4. Build, Testing & Quality Verification

Before submitting a Pull Request, agents must verify that:
1. **Automated Unit Tests Pass**: Run `bun run test` (Vitest suite).
2. **TypeScript & Build Compiles**: Run `bun run build` (`tsc -b && vite build`).
3. **No Superficial Symptom Patches**: Never delete tests or wrap broken code in silent `try/catch` blocks. Identify and fix root causes cleanly.

---

## 🎯 5. Target User Persona

- **Audience**: 50+ year old C&R (Curio & Relic) collectors who may not be tech-savvy.
- **UI Guidelines**:
  - Clean, accessible typography and high-contrast dark themes.
  - Plain, reassuring English without confusing technical jargon.
  - Keyboard accessibility (Escape key modal dismissals, shortcut keys).
  - Clear confirmation dialogs for destructive or locking operations.
